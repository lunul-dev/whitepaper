Abstract

OVERVIEW

As decentralized finance and enterprise blockchain adoption mature, resolving the tension between public-ledger transparency and financial confidentiality is essential. Fully public ledgers expose account balances, transaction histories, counterparty relationships, and smart contract state transitions to arbitrary inspection, often revealing commercially sensitive business data.

NullNet is an EVM-compatible network architecture that unifies standard Solidity smart contract execution with zero-knowledge cryptographic privacy mechanics. Built on a Geth-derived Clique Proof-of-Authority consensus engine (Chain ID 448000), NullNet combines Pedersen commitments, Groth16 zk-SNARKs, encrypted payloads, and a spent-nullifier tracking system to deliver high-throughput execution with complete state confidentiality.

Section 01

Introduction & problem statement

DESIGN GOALS

Modern blockchain infrastructure presents a trade-off: high-performance public ledgers expose sensitive enterprise operational data, while existing privacy-focused privacy chains lack EVM composability, requiring specialized languages and unfamiliar tooling.

NullNet bridges this gap by embedding a native shielded UTXO transaction layer alongside a high-throughput EVM execution engine. This design allows developers to write, deploy, and interact with smart contracts using standard Solidity tooling while giving users native access to private transactions.

Section 02

Cryptographic & privacy architecture

SHIELDED TRANSACTIONS

NullNet operates a shielded UTXO model concurrently with EVM account-based execution. The cryptographic primitives detailed below enable confidential value transfers while ensuring complete double-spend protection across the network state.

2.1 · Pedersen commitments and blinding factors

Shielded values are stored as Pedersen commitments on the BN254 (alt_bn128) elliptic curve rather than plaintext balances. Each commitment binds the underlying value while utilizing a random blinding factor to conceal the value from external observers.

C = r · G + v · H

Where v represents the transaction value, r is the secret blinding factor, and G and H are independent generator points defined over the BN254 elliptic curve.

2.2 · Nullifiers and double-spend protection

To spend a shielded UTXO without disclosing its origin, the transaction generates a unique, deterministic nullifier derived from the spender's secret key and the UTXO index. The nullifier is published to the protocol's spent-nullifier set, preventing double-spending while keeping the original UTXO unlinked.

Nullifier = Hash(SK, UTXO_Index)

Domain-separated cryptographic hashing ensures that nullifiers cannot be inverted or linked to specific addresses or unspent outputs.

2.3 · Groth16 ZK-SNARK proving pipeline

NullNet utilizes client-side WebAssembly (WASM) provers to generate Groth16 zero-knowledge proofs. These zero-knowledge proofs demonstrate that input commitments equal output commitments and that valid nullifiers have been produced—all verified on-chain in constant time without revealing private witness data.

A(x) · B(x) − C(x) = H(x) · T(x)

Quadratic Arithmetic Program (QAP) evaluation ensures that privacy, circuit constraints, and state transition validity are mathematically enforced prior to state finalization.

Section 03

Consensus, EVM rules & network fees

NETWORK MECHANICS

NullNet uses a optimized Go-Ethereum (Geth) Clique Proof-of-Authority consensus engine operating under Chain ID 448000. The EVM runtime is configured specifically to the Paris specification target.

Consensus

Clique PoA

Delivers deterministic block times, instant finality, and high throughput through an authorized validator network.

Execution Engine

Paris EVM target

Provides robust compatibility with standard smart contract Bytecode (specifically excluding Shanghai PUSH0 opcodes for execution stability).

3.1 · Fee-only economic model & treasury routing

NullNet operates entirely without inflationary block rewards. Network validators are compensated directly through execution fees. Furthermore, smart contract wizard deployments automatically direct a fixed protocol fee of 5.0 LUN to the Lunul Foundation treasury, while a portion of all transactional gas is burned.

4.1 · Deflationary burn mechanism

To establish long-term token scarcity, 10% of all network transaction fees and wizard deployment charges are permanently burned on-chain. Dynamic gas price balancing automatically protects network access affordability as transaction volume scales.

Section 05

Conclusion

SUMMARY

NullNet introduces a robust, enterprise-ready infrastructure combining standard EVM execution with zero-knowledge state privacy. Powered by a fixed-supply, deflationary utility token (LUN), the protocol delivers high-performance smart contract support alongside confidential balances and transfers.
