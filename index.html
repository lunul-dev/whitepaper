# Abstract

As decentralized finance and enterprise blockchain adoption mature globally, the inherent tension between public ledger transparency and user financial confidentiality has reached a critical bottleneck. While high-throughput layer-1 networks successfully scale transaction execution, they do so by sacrificing user privacy—exposing account balances, transaction graphs, counterparty relationships, and smart contract execution parameters to MEV sandwich bots, state surveillance algorithms, and commercial intelligence scrapers. Conversely, legacy privacy-centric protocols often compromise throughput, user experience, developer tooling, and programmatic smart contract composability.

Lunul (NullNet) introduces an advanced institutional architecture: an EVM-compatible, high-output, parallelized zero-knowledge transaction protocol backed by a Go-Ethereum (Geth) Clique Byzantine Fault Tolerant (BFT) consensus engine operating on Chain ID 448000. By anchoring state transitions in Pedersen commitments, Groth16 zk-SNARK circuits, encrypted AES-GCM payloads, and a deterministic spent nullifier database, Lunul achieves complete transactional confidentiality alongside sub-400ms finality and high-frequency execution capacity.

1. Introduction & Problem Statement

The modern distributed ledger ecosystem remains polarized between two fundamentally flawed paradigms:

  • High-Performance Public Ledgers: Networks optimized for raw throughput (such as public EVMs and modular rollups) which broadcast all account states, transaction amounts, and token flows in plaintext, exposing corporate treasuries and high-net-worth entities to financial surveillance.
  • Anonymity-Centric Privacy Chains: Protocols that prioritize financial shielding but rely on proprietary virtual machines, exotic domain-specific programming languages, or sluggish proving times that stifle developer adoption.

Lunul reconciles these divergent goals by embedding zero-knowledge proofs directly into a dual-state architecture. Transactions are private by default—concealing sender identities, recipient addresses, and transfer amounts via cryptographic commitments—while maintaining full EVM compatibility and instant BFT settlement.

// Core Protocol Objectives
• Default Confidentiality: Obfuscating sender balances and recipient graphs via Pedersen commitments and AES-GCM payload encryption.
• Enterprise Scalability: Achieving over 100,000 TPS through parallelized execution pipelines and optimized Groth16 verification.
• Fee-Only Economic Model: Eliminating inflationary block subsidies in favor of direct public fee extraction and permanent token burns.
• Turnkey EVM Tooling: Enabling developers to deploy standard Solidity contracts targeting the Paris hardfork without modified compilers.

2. Cryptographic and Privacy Layer Architecture

2.1 Pedersen Commitments and Blinding Factors

Within the NullNet shielded pool, unspent transaction outputs (UTXOs) are not recorded as raw plaintext amounts. Instead, they are represented as cryptographic commitments on pairing-friendly elliptic curves:

$$C = r \cdot G + v \cdot H$$

Where $v$ represents the raw transfer value, $r$ is a randomly generated 256-bit blinding factor (scalar), and $G$ and $H$ are independent generator points on the BN254 / alt_bn128 elliptic curve.

2.2 Nullifier Double-Spend Protection

To prevent double-spending without revealing which UTXO is being consumed, Lunul utilizes deterministic nullifiers. When a UTXO at index $i$ is spent, the owner computes a nullifier hash using their secret spending key ($SK$):

$$\text{Nullifier} = \text{Hash}(SK, \text{UTXO\_Index})$$

The resulting nullifier hash is published to the global Spent Nullifier Set. If an identical nullifier is submitted twice, the state machine instantly rejects the transaction.

2.3 Groth16 ZK-SNARK Prover Pipeline

Client-side applications execute arithmetic circuit constraints in WebAssembly (WASM) prior to transaction broadcast. Lunul employs the Groth16 proving system over pairing-friendly curves. Quadratic Arithmetic Programs (QAPs) translate circuit constraints into polynomial relations satisfying $A(x)B(x) - C(x) = H(x)T(x)$, ensuring constant-size proofs verified in $O(1)$ time by validators.

3. BFT Consensus, Paris EVM Rules & Fee Economics

NullNet operates a customized Go-Ethereum (Geth) Clique Proof-of-Authority consensus engine optimized for sub-second finality. Genesis block parameters lock the network to Chain ID 448000, enforcing strict Paris EVM opcode rulesets and prohibiting the PUSH0 opcode.

// Fee-Only Economic Model & Treasury Routing

Unlike legacy networks dependent on inflationary block subsidies, Lunul operates on a sustainable fee-only economic model. Validators process transactions for explicit public fees attached to the ZK balance relation. Furthermore, platform contract deployments route a flat 5.0 LUN fee directly to the Lunul Foundation treasury wallet (0x8632fa855d5Dc6b59A3cF892d72CF4a94F182AAE) to fund ongoing core protocol development.
